# Session 7: 单系统重构 + 操作回放闭环

**日期**: 2026-06-14
**阶段**: finalization → complete
**置信度**: 98%

## 本轮目标

从双系统（Umami + 独立 RRWeb）重构为单系统（Umami 内置录制 + a11y-enhancer.js），并实现录制→存储→读取→回放的完整闭环。

## 完成事项

### 1. 单系统架构重构
- 去除 rrweb.min.js 和独立 event-receiver 依赖
- 创建 a11y-enhancer.js：captureA11yContext + capture-phase 监听 → umami.track() 发送
- A11y 语义数据存入 Umami event_data 表，复用 Umami 存储能力
- index.html 简化为 Umami script.js + recorder.js + a11y-enhancer.js
- 旧方案备份为 index-v1-rrweb.html（可回滚）

### 2. 采集端修复与增强
- **Checkbox 嵌套 label 修复**：`el.closest('label')` 提取 `<label><input>Text</label>` 的 name
- **Select 选项值捕获**：change 事件记录 selectedText（如 "CSV File"）
- **输入值采集**：input 事件记录 inputValue，保留 sanitizeValue 隐私脱敏（password→[REDACTED], email→{email}）
- **双层 session 模型**：
  - sessionId：复用 Umami session（从 cache JWT 解码），关联 session 表
  - pageSessionId：每次页面加载生成新 UUID，用于回放和 SOP 切分

### 3. 操作回放工具 (replay-a11y.js)
- 从 Umami PostgreSQL 读取 A11y 事件（fetch_events.py 辅助）
- 事件去重：300ms 内同 role+name+eventType 只保留一条
- Checkbox click+input 去重：避免二次点击取消勾选
- TOON → Playwright ARIA 定位器自然映射：`getByRole(role, { name })`
- 支持 --headed / --dry-run / --session / --url 参数
- 输入值使用采集到的真实值（不再用占位符）

### 4. 回放验证结果
- 双系统方案：7/7 PASS (100%)
- 单系统方案：12/12 PASS (100%)
- 含输入值精确回放：12/12 PASS（1111→222→3333 三轮搜索完整复现）
- checkbox + select 回放修复后：10/10 PASS

## 关键决策
1. **TOON 与 Playwright ARIA 对齐**：captureA11yContext 的 role/name 模型与 Playwright getByRole 完全对齐，实现"录制即回放"
2. **单系统优于双系统**：Umami 内置 RRWeb 已够用，A11y 语义层是差异化核心
3. **pageSessionId 独立于 sessionId**：pageSessionId 按页面加载切分，适合 SOP 提取；sessionId 关联 Umami session 表，适合浏览器级分析

## 数据流
```
用户操作 → a11y-enhancer.js (captureA11yContext + sanitizeValue)
         → umami.track('a11y-action', payload)
         → Umami /api/send
         → PostgreSQL: website_event + event_data
         → fetch_events.py 读取
         → replay-a11y.js (Playwright getByRole 回放)
```
