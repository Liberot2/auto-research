# SOP 自动化系统：从操作录制到智能执行

> 让 Agent 学会"怎么做"，而不只是"做什么"

---

## 一、问题与机会

### 行业现状

安全运营平台、运维管理平台、业务系统中存在大量标准化的操作流程：告警处置、漏洞修复、工单流转、报表导出、配置变更。这些流程目前主要依赖人工执行——即使流程本身是标准的，每次执行仍需要人登录系统、点击按钮、填写表单、确认提交。

### 核心痛点

**1. 人的时间被消耗在重复的标准操作上**

平台中 70%+ 的操作是重复性的：相同的流程，只是参数不同（不同的告警 ID、不同的时间范围、不同的客户名称）。资深工程师每天花费大量时间在"按流程点按钮"上，这些时间本应该用于真正的分析和决策。

**2. 操作知识存在人脑里，不在系统里**

每个团队都有几个"最懂流程"的人。新人遇到问题第一反应是问他们："这个该怎么操作？"操作流程散落在 Word 文档、聊天记录、个人笔记里，随着人员变动不断流失和重建。组织花在"知识传承"上的隐性成本远超想象。

**3. 想做自动化，但写脚本成本太高**

传统自动化（RPA、脚本）需要专业开发者深入理解业务流程后编写代码。一个简单的"告警处理"流程可能需要 2-3 天的开发调试。而且页面一旦改版，脚本就失效，维护成本持续累积。结果是：很多明明可以自动化的流程，因为开发成本太高而一直靠人工。

**4. 自动化测试覆盖不足**

QA 团队想对平台做回归测试，但测试脚本的编写速度跟不上功能迭代速度。测试人员"会测但不会写代码"，开发人员"会写代码但不了解业务流程"。测试覆盖长期不足，线上问题频发。

### 我们的方向

**通过埋点采集真实的工作经验，清洗整合出可靠的 SOP，让 Agent 自动执行，让人从重复操作中解放出来。**

```
人在平台上自然操作
     ↓ 埋点自动采集
原始操作事件（每次点击、输入、选择）
     ↓ 清洗 + 聚类 + SOP 识别
标准操作模板（参数化，可复用）
     ↓ Agent 可执行的自动化流程
     ├── 自动化处置：告警来了 → Agent 按 SOP 自动处理
     ├── 自动化测试：CI/CD 中自动跑 SOP → 验证功能正常
     └── 操作标准化：每个人是否按 SOP 操作？偏差在哪？
```

**人实施一遍 → 被转译成 Agent 可复用的动作。**

### 创造的价值

| 价值维度 | 具体体现 |
|---------|---------|
| **效率** | 重复操作从人工 15 分钟 → Agent 30 秒，7×24 不间断 |
| **知识资产化** | 操作经验从"个人技能"变为"组织资产"，人员变动不丢失 |
| **自动化门槛降低** | 不需要写代码，操作一遍就是自动化流程，开发成本从天级降到分钟级 |
| **质量一致性** | 每次执行都按标准 SOP，消除人为遗漏和操作差异 |
| **测试覆盖提升** | 业务人员操作一遍 → 自动生成测试用例，零代码门槛 |
| **合规可审计** | 每次实际执行被自动采集验证，操作合规性 100% 可追溯 |

## 二、系统架构

```
用户操作
  │
  ▼
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  采集层   │────▶│  提取层   │────▶│  执行层   │────▶│  验证层   │
│          │     │          │     │          │     │          │
│ 浏览器    │     │ 事件序列  │     │ Agent +  │     │ 期望 vs  │
│ 埋点 SDK  │     │→SOP模板  │     │ browser  │     │ 实际采集  │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
     │                │                │                │
     ▼                ▼                ▼                ▼
  Umami DB       SOP 库(YAML)     agent-browser     验证报告
```

### 各层说明

**采集层 — a11y-enhancer.js**
- 注入任何网页，零侵入
- 捕获用户每次点击、输入、选择
- 自动提取 A11y 语义：元素角色（role）、名称（name）、状态（state）、上下文（context）
- 输入值自动脱敏（密码→[REDACTED]，邮箱/手机→类型标记）
- 数据存入 Umami PostgreSQL，复用现有基础设施

**提取层 — extract_sop.py**
- 从原始事件序列中，按页面区域（tabpanel/dialog）自动切分操作片段
- 参数化：输入框的值→参数（如 {keyword}、{format}），按钮点击→固定步骤
- 合并去重：相同区域的多次操作合并为通用模板
- 输出标准 YAML 格式的 SOP 模板

**执行层 — agent-browser**
- 读取 SOP 模板 + 业务参数（如客户名、报告类型）
- 通过浏览器 Accessibility Tree 自适应定位元素
- 页面改版、元素改名时仍能找到正确目标
- 支持条件分支、异常重试、状态验证

**验证层 — sop_verifier.py**
- 执行后自动采集实际操作
- 与期望 SOP 步骤对比
- 检测：步骤缺失、多余操作、顺序偏差、参数不匹配
- 输出结构化验证报告

## 三、已验证的核心能力

### 采集精度

| 指标 | 结果 |
|------|------|
| A11y 语义捕获率 | 100%（role/name/state/context 全覆盖） |
| 输入值采集 | 精确到字符级别 |
| 隐私脱敏 | 密码、邮箱、电话自动脱敏 |
| 元素类型覆盖 | 按钮/输入框/下拉/复选框/TAB/对话框 |

### SOP 提取效果

```
原始录制（37个事件）
  → 去重（15个有效操作）
  → 按区域切分（4个操作片段）
  → 合并去重（4个标准 SOP）
  → 参数化（6个可变参数）
```

**自动提取的 SOP 示例：**

```yaml
sop:
  name: "导出报告"
  context: "Export Options"
  steps:
    - action: select     # 选择导出格式
      role: listbox
      name: "Export format"
      param: format      # ← 参数化：客户指定 PDF/CSV/JSON
    - action: toggle     # 勾选图表
      role: checkbox
      name: "Include charts"
    - action: click      # 点击导出
      role: button
      name: "Export Report"
    - action: click      # 确认
      role: button
      name: "Confirm"
```

### 执行能力

| 执行方式 | 成功率 | 速度 | 适应性 |
|---------|--------|------|--------|
| Playwright 确定性回放 | 100% | 快（20s/15步） | 页面改版即失效 |
| agent-browser 自适应执行 | 100% | 中（60s/15步） | 页面改版仍可执行 |

**参数化执行验证：**

同一 SOP 模板，不同参数，均成功执行：

| 参数 | 录制值 | 执行值1 | 执行值2 |
|------|--------|---------|---------|
| 搜索关键词 | "q3 summary" | "weekly metrics" | "agent-browser demo" |
| 导出格式 | CSV | JSON | PDF |
| 用户名 | Alice | Bob | lgy |
| 邮箱 | {email} | bob@corp.com | 123344 |

### TOON 格式 — Agent 的操作语言

我们设计了 **TOON（Task-Oriented Object Notation）** 紧凑格式：

```
click r:button n:"Search" s:{focused:true} ctx:tabpanel("Search")
input r:textbox n:"Search reports" v:"q3 summary" ctx:tabpanel("Search")
change r:listbox n:"Export format" v:"CSV File" ctx:tabpanel("Export Options")
click r:checkbox n:"Include charts" s:{checked:true} ctx:tabpanel("Export Options")
```

**LLM 消费验证：** 将 TOON 序列喂给 Claude，6/6 推理任务全部通过：
- 用户意图识别
- 页面流程追踪
- 表单字段分析
- 隐私风险检测
- UX 改进建议
- 操作证据引用

## 四、核心价值：人为操作 → 自动化流程

### 一句话描述

> 资深员工操作一遍，系统自动固化为可复用的自动化流程；之后任何人（或 Agent）只需提供参数，系统自动执行并验证。

### 传统自动化 vs 我们的方案

| 步骤 | 传统 RPA/自动化 | 本系统 |
|------|----------------|--------|
| 学习操作 | 开发者编写脚本 | 资深员工自然操作一遍 |
| 固化流程 | 人工翻译为代码 | 系统自动提取 SOP 模板 |
| 参数化 | 开发者手动编码 | 自动识别哪些是变量、哪些是固定的 |
| 执行 | 脚本硬编码执行 | Agent 自适应执行（页面改版不失效） |
| 维护 | 页面改版需重写脚本 | Agent 自动适应新页面结构 |

### 完整转化流程

```
第 1 步：固化（一次性）
  资深员工正常操作 → 采集层捕获每个操作的语义
  → 提取层自动生成参数化 SOP 模板
  → "搜索{关键词}→选择{格式}→导出→确认"

第 2 步：复用（无限次）
  业务系统传入参数 → Agent 读取 SOP 模板
  → agent-browser 自适应执行
  → "搜索'Q3报告'→选择PDF→导出→确认"

第 3 步：验证（每次执行后）
  采集层自动记录实际执行过程
  → 验证层对比期望 SOP vs 实际操作
  → "12/12 步骤匹配，执行正确"
```

### 典型应用

**1. 运维流程固化**
- 资深 SRE 操作一次告警处理流程 → 固化为 SOP
- 后续告警自动触发执行（填入告警ID、处理人）
- 新人无需培训，系统自动按标准流程操作

**2. 业务流程自动化**
- 财务人员操作一次月报导出流程 → 固化为 SOP
- 每月定时自动执行（填入月份、部门）
- 跨系统操作（从 A 系统取数 → 填入 B 系统提交）

**3. 操作标准化**
- 专家的操作方式固化为标准 SOP
- 每个人的实际操作被自动采集
- 验证层检测：谁的操作偏离了标准流程？哪里偏离？

**4. 流程传承**
- 资深员工离职前操作一遍核心流程 → 固化为 SOP 库
- 操作知识不再依赖个人，成为组织资产
- 新人通过 Agent 按标准 SOP 执行，零学习成本

## 五、技术亮点

### 1. A11y 语义对齐 — 不是录制像素，而是录制意图

传统录屏：记录鼠标坐标、截图序列 → 无法被 Agent 理解
RRWeb 录制：记录 DOM 变化 → 数据量巨大，需要回放器
**我们的方案**：记录 ARIA 语义（role/name/state）→ Agent 直接可消费

```
传统: "用户在 (320, 150) 位置点击了"
RRWeb: "DOM 节点 #search-btn 的 class 从 idle 变为 active"
我们:  "用户点击了 role=button name=Search"
```

### 2. TOON 压缩格式 — 让 Agent 高效理解操作

| 格式 | 大小 | Agent 可读性 |
|------|------|-------------|
| 原始 DOM 事件 | ~50KB/session | 不可读 |
| Compact JSON | ~5KB/session | 需解析 |
| **TOON 格式** | **~1.5KB/session** | **直接可消费** |
| 行为摘要 | ~500B/session | 可消费但丢细节 |

### 3. 参数化模板 — 录制一次，N 次复用

```
录制: 搜索 "q3 summary" → 导出 CSV → 发送给 Alice
模板: 搜索 {keyword} → 导出 {format} → 发送给 {recipient}
执行: 搜索 "weekly report" → 导出 PDF → 发送给 Bob
```

### 4. 双层验证 — 不仅执行，还要确认

```
执行前: SOP 模板定义"应该做什么"
执行中: agent-browser 自适应"实际怎么找元素"
执行后: 验证层确认"是否真的做对了"
```

## 九、总结

**核心价值：操作知识自动化**

> 传统方式：人学会操作 → 人写文档 → 人培训人 → 人执行 → 人检查
>
> 我们的方式：人操作一次 → 系统自动学会 → Agent 自适应执行 → 系统自动验证

**三句话总结：**

1. **采集**：注入一段 JS，捕获用户操作的 A11y 语义（不是坐标，是意图）
2. **执行**：Agent 读取操作模板 + 业务参数，自适应地在浏览器中执行
3. **验证**：执行后自动对比期望步骤 vs 实际操作，确保正确性

**已验证：** 采集 100% 覆盖、提取 4 个 SOP 类型、执行 100% 成功、验证支持多维度对比。
